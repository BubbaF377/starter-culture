# StarterCulture

Working name: **StarterCulture** (styled as one word, no space). Brand/marketing website for StarterCulture, Christian's small AI-native software development studio, hosted at starterculturestudio.com.

## Vision

A brand site that introduces StarterCulture as a small software development studio doing AI-first, AI-native development, and showcases the studio's products — starting with Devlore. The site should feel light, clean, and minimal, and give the studio a real home on the web that can grow to list future products, plus room for a company/team page and an eventual client portal.

## Requirements

1. Homepage (`src/pages/index.astro`) is a single scrolling page with sections: header/nav, hero, studio/about, products, contact, footer. `src/pages/about.astro` and `src/pages/clients.astro` are separate pages linked from the footer, not part of the homepage scroll.
2. Visual style: light, clean, minimal aesthetic built around the studio's palette — cream (`#F5EFE1`/`#FBF8F1`), terracotta (`#B5482B`), dark brown (`#2B2320`), plus a third complementary color, moss green (`#3F4B3D`), used on the header and footer (with cream-toned text/nav for contrast on that dark background).
3. Logo assets live in `public/assets/starter-culture-logo.svg` (wordmark) and `public/assets/starter-culture-avatar.svg` (icon-only mark). The header/footer wordmark is also inlined directly in `src/components/Header.astro`/`Footer.astro` — keep its `<text>` fill and `font-family` sans-serif (matching the uploaded logo asset), not serif.
4. Brand name is styled **StarterCulture** — one word, no space — in all page copy, titles, meta tags, and aria-labels. (The logo's wordmark graphic itself uses a lowercase stylized "StarterCulture" per the logo file.)
5. Homepage hero hierarchy (redesigned from the original single-headline layout): the **"StarterCulture Software Studio"** brand line (`.hero-brand span`) is the prominent, large sans-serif hero text; the `<h1>` ("Small studio. Big ideas. AI-native.") is a small italic tagline beneath it, not the dominant headline. Section titles (`<h2>`) are sized larger (`clamp(32px, 5vw, 44px)`) than the original draft for more visual weight. The Contact section has a `--paper` background (matching the Studio section) to visually separate it from Products above it.
6. Products section lists each product with a status pill reflecting its actual progress — "In development" or "Beta" (more stages may be added later as needed). Devlore currently uses a "Beta" pill, with this description: "Devlore is an agentic knowledge base that automatically documents every push across your project repos, with human review only at release time." Devlore also links out to its npm package: `https://www.npmjs.com/package/@starterculture/devlore`.
7. Contact section/footer uses `dev@starterculturestudio.com` as the studio contact address.
8. Site is built with **Astro** (`astro.config.mjs`, `src/layouts/Layout.astro`, `src/pages/*.astro`, `public/` for static assets/CNAME/robots.txt) — same stack/repo shape as the studio's other site, `heartland-fermenters-guild`. Shared header/footer markup lives in `src/components/Header.astro` (takes a `links` prop for per-page nav items) and `Footer.astro`; shared tokens/typography/header/footer CSS live in `src/styles/site.css`, imported by each page. Page-specific styles stay scoped in each page's own `<style>` block.
9. **About page (`src/pages/about.astro`)** — a fuller company narrative than the homepage's short studio blurb, plus a team section (a card per person with a photo and short bio, starting with Christian, with placeholder slots for future teammates). Currently a wireframe: placeholder avatars and "bio coming soon" copy, with a "Page in progress" badge, ready to swap in real photos/bios when available. Linked from the site footer as "About."
10. **Client portal (`src/pages/clients.astro`)** — a login-gated area where clients can check the status of what's being worked on for them. Currently a wireframe only: a non-functional login form (email/password fields, disabled, no submit action), clearly labeled "Coming soon" — no real authentication or client dashboard content exists yet. Linked from the site footer as "Client Portal."
11. Deployment target: GitHub Pages from this repo (`BubbaF377/starter-culture`, public), with `starterculturestudio.com` as the custom domain (via `public/CNAME`, which Astro copies into the build output, and the repo's Pages `cname` setting). DNS is hosted at Porkbun: 4 apex A records point at GitHub Pages' IPs (`185.199.108.153`/`.109.153`/`.110.153`/`.111.153`), and a `www` CNAME points at `bubbaf377.github.io`. GitHub's HTTPS certificate for the custom domain is issued and approved for both the apex and `www`. The live site tracks the latest published GitHub Release, not raw `main` HEAD — `.github/workflows/pages-deploy.yml` builds with `withastro/action@v3` and deploys on each `release: published` event (checking out that release's tag), so publishing a new version of the site means cutting a new release/tag. The GitHub Pages environment's deployment branch policy must allow the tag pattern used for releases (currently `v*`) in addition to `main`.
